# M40 — Final Defense Stabilization, Integration and Deployment Handoff

## Goal
Freeze features and validate everything needed for a safe final demonstration across Student, Administrator, Department Head and Dean. Read project rules and M36–M39 reports. Operate only in local isolated development/staging; do not deploy or edit live Supabase/Render settings or production records without explicit owner authorization. User handles Git integration/push.

## Safety / readiness gates
- Check branch divergence and M35 deployment config; audit additive migrations M37–M39 for PostgreSQL, including `prediction_attempt_grants`, account provisioning and review workflows. Never `migrate:fresh` or truncate. Backup before any local migration exercise; preserve APP_KEY and encrypted records. Verify Render deployment branch ownership/auto-deploy trigger; don't merge into production branch automatically.
- Run full Laravel (SQLite) and full PostgreSQL suites (using direct `php vendor/bin/phpunit --configuration=phpunit.pgsql.xml`); `npm run build`, available Python FastAPI tests, Docker config and local HTTP research client. Report skips distinctly; don't misrepresent untested cases as passing.
- Student smoke: student number login, assessment questionnaire 36-item published v1 and versioned drafts, six-dot progress and live saved/answered counts, save/resume/discard, skills archive/restore, grade upload/correction/year & semester validation/atomic confirm/history, INC/5.00/Dropped/Unofficially Dropped, two-per-Asia/Manila-day quota, approved grant, loading overlay and duplicate-click prevention, snapshot immutability.
- Admin smoke: each list/filters/newest-first/actions; CLAS academic structure guard; PSOC controlled inputs; interventions and activity ranges; account provisioning/login; grant authorization/audit.
- Department Head: assigned students only, correct review flow, exports/printing, no raw private answers. Dean: aggregates only, no student-level access even via direct URL/export.
- UX checklist: every modal footer pinned and keyboard accessible, thin visible scrollbars, proper mobile viewport/safe-area and no overflow, success only after commit, SweetAlert confirmation for consequential actions, no `Livewire method undefined` or Chart.js errors. Verify browser console and real workflows, not page GET alone.
- Scientific disclosure: `placeholder-heuristic-v0` historic snapshots and `-v1` current estimates not clinically or statistically validated; Pianda/UCI models served by FastAPI research-only, no verified UCC input map. Never switch `PREDICTOR_DRIVER` to `http` for real students on assumption of compatibility; never call readiness score a hiring probability. If FastAPI deployment is attempted, use separate service and real token, test health/readiness, model artifacts, cold-start behavior and explicit research fixtures; do not silently impact student workflow.
- Render/Supabase: release checklist for professor including production secrets, health routes, HTTPS/trusted proxy, storage durability, no seed overwrite, disabled public demo credentials, deploy branch, rollback, migrations, DB encryption key retention. Production deployment is separate explicit approval.

## Deliverables
Concise reproducible final demo checklist (accounts/URLs only from verified local config, no secrets), known-gaps/limitations page, exact test results, verified browser walkthrough across four roles, migration safety report, no data changes outside disposable synthetic fixtures, commit hash. Fix only confirmed blockers; don't begin new features. Commit locally, never push/merge/deploy.
