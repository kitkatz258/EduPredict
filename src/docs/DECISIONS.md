# EduPredict implementation decisions

One line per decision. Record choices made where the spec is silent.

- M0: Installed Livewire 4.4 (latest stable compatible with Laravel 12) as class-based components; did not pin to v3.
- M0: Demo table lists `users` until domain tables exist in later milestones; it is a public development page at `/demo/table`.
- M0: Application timezone is `Asia/Manila`; currency is PHP (no money library yet).
- M0: Guest welcome page is a branded landing with a non-functional sign-in card until Breeze auth lands in M1.
- M0: Chart.js is imported in `resources/js/app.js` as `window.Chart`; Alpine is not installed separately.
- M0: Uploaded grade files will be deleted after confirmation (recorded here as required by the spec; implemented in M3).
- M1: Added `users.must_change_password` in the role-fields migration so M2 staff accounts can force a password change without another schema edit.
- M1: Seeded students use student numbers `SYN-####` and emails `syntheticN@edupredict.test`; they are synthetic demo data, never production records.
- M1: Demo account password is `Password123!` (development only).
- M2: Student self-registration requires an exact match on student number and program, and a case-insensitive match on first and last name, against `institution_students`.
- M2: Staff accounts are created with a generated temporary password and `must_change_password` until the first successful change.
- M2: Dean creation requires `college_id`; department-head creation requires `program_id`; faculty program is optional.
- M2: Adviser assignment uses one faculty picker plus a multi-select student list (one checked student is single assignment; several is bulk).
- M2: CSV import keeps valid rows and reports invalid rows instead of aborting the whole file.
- M2: Administrators cannot deactivate their own account.
- M3: Grade-report `source` values are `manual`, `pasted`, `pdf_text`, `grid_ocr`, `generic_ocr`, or `ai_extracted` (spec listed only manual|ai_extracted).
- M3: Dropped (DRP/W) rows are excluded from GPA; INC uses `grades.inc_gpa_weight` (default 4.00, confirm with registrar); NSTP prefixes are excluded; PATHFIT counts.
- M3: Confirmed grade reports may be deleted by the student and re-entered; a second confirmed report for the same term is rejected.
- M3: `is_major_subject` defaults to false until a program curriculum list exists.
- M3: Real portal samples live in gitignored `cursor/samples/` as `grade_sample_a.png`, `grade_sample_b.png`, and `grade_sample_c.pdf` (the spec’s `Screenshot_2026-10-05_*` names are accepted as alternates). OCR descriptions stay uppercase as printed; program text stays the full “Bachelor of Science in Information Systems” heading. OCR tests skip only when those files or python/tesseract are missing.
- M4: Socioeconomic and skills rows stay readable only by the owning student. Staff do not get the raw income or skills forms.
- M4: Completeness is an equal split of academic (a confirmed grade report), socioeconomic (saved and not a draft), and skills (saved and not a draft). An empty skills list can still be marked complete.
- M4: Skills are entered one item per line; paired lists use `name | detail`. No new tables — the M1 socioeconomic and skills tables already match the spec, and socioeconomic columns stay encrypted.
- M5: Seeded questionnaire items stay `is_draft=true` and `is_active=true`. Students answer every active item; the draft flag marks the research scale, and the non-clinical footer always shows.
- M5: Procrastination scores rise with delaying behavior. The other four constructs rise with the positive behavior. Reverse items use `6 - value`. Construct score is `(mean - 1) / 4 * 100`.
- M5: Retakes insert a new response. `FeatureBuilder::build()` uses the latest submission's construct scores.
- M5.5: Draft socioeconomic and skills rows, and unconfirmed grade reports, are omitted from `FeatureSet`. Confirmed-term count from `AcademicSummary` decides `limited_history`, not the denormalized `students.semesters_completed` column.
- M5.5: Placeholder weights live in `HeuristicPredictor`. Household size and living arrangement are snapshotted and not scored. Income and employment use small weights. `+` helps the student and `-` hurts, including on dropout where a higher probability is `-`.
- M5.5: `http` and `onnx` predictor drivers throw until a later phase. The placeholder version string is the `HeuristicPredictor::MODEL_VERSION` constant.
- M6: Prediction requests insert a new row and leave older rows unchanged. `program_shift_flag` stays `none` until M7, and that indicator is not shown yet.
- M6: A request needs profile completeness of at least `prediction.min_profile_completeness` (default 80). With four equal sections, that means all four are saved. Cooldown is `prediction.cooldown_hours` (default 24) after the latest prediction.
- M6: The assigned adviser gets a database notification naming the advisee. No socioeconomic values are included. A student with no adviser still gets a stored prediction.
- M6: Faculty, department heads, deans, and administrators open prediction history from a scoped student table. Dean and institution charts stay in M10. Seeded M1 prediction rows stay in place; new requests use the placeholder predictor, and the results page accepts both factor shapes.
- Performance: Before M7, HTTP samples were robots.txt 0.07–0.16s, a one-file PHP script 0.04–0.15s, Laravel `/up` 25–36s TTFB across four requests, and `/login` 38–39s TTFB. Apache OPcache was already on (about 107k hits; misses did not rise on a second boot). Bootstrap time was spread across autoload, config, and provider registration. `stat` of 37 bind-mounted PHP files took 0.9–1.1s and `realpath` 1.2–1.7s; `stat` of 30 container-local files took about 1ms. After bootstrap, the student dashboard ran 21 queries totaling 53ms and the faculty Livewire dashboard ran 14 queries totaling 32ms; `SELECT 1` was 1ms. No Vite hot file. The primary cause is Windows/Docker bind-mount filesystem latency during PHP bootstrap, not N+1 queries, Livewire work, or frontend assets.
- Performance: No application change. Do not turn on config, route, or view caches, or `opcache.validate_timestamps=0`, for day-to-day development. The safest reproducible improvement is to clone the repo onto the WSL2 Linux filesystem and run Docker from there, so `src/` is not a Windows bind mount. A narrower option is a named volume for `vendor/` only, followed by `composer install` inside the container.
- M7: Program-shift thresholds use the Philippine scale, where a higher GWA is weaker. Program fit requires at least 6 major units and 3 other units, major GWA at least 2.75 or one failed major, other GWA at or below 2.25 with no other failures, and a major-minus-other gap of at least 0.75 (a failed major can satisfy the gap). Study habits, motivation, and engagement at 60 or above are healthy. Engagement or motivation at 40 or below, time management at 40 or below, or procrastination at 70 or above is the disengagement behavior signal. Broad poor performance is overall GWA at least 2.75 or at least 2 failed subjects, and only when the major-subject pattern is not concentrated. Mixed is concentration plus that behavior signal. Otherwise the flag is none. The indicator is qualitative, has no percentage, and is not a trained model. `is_major_subject` still defaults to false, so program fit appears only when major subjects are marked.
- M8: PSOC rows are a starter set, verify against the official PSA PSOC 2012 before final submission. Compatibility is program relevance 45, skill-tag overlap up to 40, and GWA strength up to 15 (1.75 or better = 15, then 12, 8, 4, and 0 past 3.00). Bands are 80–100 strong, 65–79 good, 50–64 possible with growth, and below 50 a longer pathway. The top 5 are stored on the prediction that produced them. `matched_skills` and `missing_skills` are extra JSON columns so the card stays stable. Explanations are one de-identified AI call for all five, cached by payload hash for 30 days, with a template fallback. PHPUnit forces `AI_API_KEY` and `AI_MODEL` empty so the suite cannot call OpenRouter unless a test sets config and fakes HTTP. Career matches are shown to the owning student. The admin PSOC screen is a directory, not the full editor (that stays for M11).
- M9: `interventions.targets_factor` is a JSON list of factor keys (plus `program_fit`, `disengagement`, and `general`). An action is chosen only for moderate or high risk, at most 5, ranked by the sum of hurting-factor magnitudes (direction `-` on dropout or employability; flat seeded factor lists count too). A program-shift match adds `interventions.shift_rank_bonus` (0.5) to that rank only and is never shown as a percentage. If nothing matches, interventions tagged `general` are used. Attendance monitoring requires high risk. Students see one support sentence and not the action list. Faculty and department heads can mark the latest prediction's actions reviewed; deans and administrators can read them. One de-identified AI call rephrases the chosen codes and any other code is discarded. Missing or empty AI text keeps the stored description (`rule_based`). Phrases longer than 1200 characters are discarded. Seeding writes the description and does not call the AI. The intervention editor stays in M11.
- M10: Dashboard risk, employability, year level, program comparison, and the month trend all use the latest prediction per student (newest `created_at`, then highest id). Assessments this year counts every stored prediction in the calendar year, including older history. There is no date-range filter. Employability bands are 0–19, 20–39, 40–59, 60–79, and 80–100. Risk and program-shift figures on dashboards are counts, not percentages. Program-fit concern on the faculty page counts `program_fit` and `mixed`. Unreviewed high risk means the latest prediction is high and has no actions or at least one action without `reviewed_at`. CSV export is on the shared scoped student table for every staff role that can open it; the audit action is `students.export` and the log stores the row count and filters, not names. Seeded prediction timestamps are spread across six month-starts so the trend chart has more than one point.
- M11: Colleges, programs, PSOC rows, and interventions are edited in place and not deleted, because students, career matches, and recommended actions reference them. Editing a catalog row does not rewrite stored predictions, scores, or phrased actions. A user's role is recorded on `account_created`; later adviser changes use `adviser_assigned`. There is no separate role-edit screen. Staff views of a student record log `student_record_viewed` without socioeconomic values; a student opening their own record does not. Consent text lives in `config/edupredict.php` under version `v1`, and registration stores that version. Account deletion is a request an administrator approves or rejects; approval deactivates the login through the existing account audit and keeps prediction history. Personal export is JSON or a text PDF and omits institutional action titles. Session idle time defaults to 30 minutes. AI calls stop at `AI_DAILY_LIMIT` and `AI_PER_MINUTE_LIMIT` (default 20) and then use the existing fallbacks. Content-Security-Policy allows inline and eval script because Livewire and Alpine need them. Login stays limited to 5 attempts per email and IP. Grade uploads stay limited to the configured size and pdf/png/jpg/jpeg/webp/txt/csv.
- M12: The synthetic cohort keeps 12 high, 12 moderate, and 36 low predictions. Shift labels on that cohort are disengagement for high, program-fit for moderate, mixed when the student index modulo 5 is 2, and none otherwise. Named rows are still synthetic. Sam Student has no prediction so the live request flow stays available. Page titles come from the route name. Error pages 403, 404, and 500 use a small branded layout that does not depend on Vite. The About page states the placeholder version, the qualitative program-shift rule, and the deterministic career and action rules.
- M13: Active roles are Student, Department Head, Dean, and Administrator. `faculty` stays in the enum as a legacy value so old rows load, but those accounts cannot sign in, cannot be created, and get no notifications. Faculty users, `students.adviser_id`, and old `AdviseePredictionReady` notifications are kept, not deleted. The pilot scope is UCC CLAS with eight programs, marked by `colleges.is_active` and `programs.is_active`. Other colleges and programs are set inactive and kept for history. The existing CLA college row is renamed to CLAS in place, and existing BSIT, BSCS, BSIS, and ABCOMM rows move into CLAS with the same ids. The hierarchy is College, Department, Program, Student. The grouping into Communication, Public Administration, Computer Studies (BSCS, BSEMC, BSIS, BSIT), Mathematics, and Psychology is an assumption until UCC confirms it. A Department Head sees students in their department, or only their program when `program_id` is set. The Dean gets aggregates for the active programs of their college and is denied every student-level route, component, and export in the backend. Legacy-program students stay visible to the Administrator and are left out of aggregates. Registration and the institution import accept pilot programs only. Consent v2 describes the new scope. Existing v1 consents stay valid and are not re-prompted. Prediction notifications go to the in-scope active Department Heads.
- M14: Students authenticate with `students.student_number`; their email remains available for password recovery and cannot be used to sign in. Staff authenticate with email through the same field. `/` redirects guests to sign-in and authenticated users to their dashboard. The public About route is removed, and its unique model-limit disclosures live on Privacy. Students use a top navigation with Dashboard, Assessment, History, profile/settings, and logout. Staff use a fixed responsive sidebar. Remix Icon supplies interface icons. SweetAlert2 handles reusable toasts and confirmations, while a top progress bar, busy buttons, Livewire loading states, and form guards prevent duplicate actions.
- M15: `/student/assessment` is the single resumable student workflow with Questionnaire, Skills & Experience, optional Grades, and Review steps. The old profile, questionnaire, and grades URLs redirect into the appropriate Assessment step. Workflow progress reports saved sections only and makes no accuracy claim. Grades are not a readiness requirement; when none exist, the feature snapshot keeps academic values null and the estimate is lower confidence. Existing questionnaire items are retained as `draft-v1` academic-behavior definitions; responses store the exact definition version, and an item with student answers cannot be edited, activated/deactivated, or published in place. A later approved version must create new definitions. Socioeconomic context remains encrypted and owner-only. Employability themes are configuration and UI placeholders only: no final questions, scores, construct weights, or model features were invented. Structured skills and grade redesign remain assigned to M16 and M17.
- M16: Skills & Experience entries are structured rows in `student_skills` (name only; no category, proficiency, or evidence field because no requirement retains them), `student_certifications` (title, issuer, issue year or exact date, optional expiry, credential reference, and description), and `student_work_experiences` (type, organization, role, start date, end date or ongoing, and description). OJT/Internship is the `ojt_internship` experience type and feeds `internship_count`; every other type feeds `work_experience_count`. Entries are archived (`archived_at`), not deleted, and can be restored. `skills_experiences` remains the section row: `is_draft` false means the student marked the section saved, and entries count toward features only then. An additive migration copied the existing JSON lists into the new tables with a `legacy_source` marker (legacy free-form work experience became type `other`, internship hours went to the description) and left every JSON column untouched. Projects are no longer collected or shown in the Assessment, and they no longer feed features, career tags, or the heuristic. Legacy project JSON stays stored and appears in the student's data export. New predictions store `assessment_snapshot.skills_experience` with the exact active entries used. Career skill tags come from that snapshot, and older predictions without one fall back to current entries. Raw entries stay owner-only.
- M17: INC has no numeric grade. It is stored as the `INC` token with `subject_grades.is_incomplete` true, is never a failure, and is left out of the GWA numerator and denominator (this replaces the M3 `grades.inc_gpa_weight` rule, which is removed). Any INC makes the GWA provisional; `AcademicSummary` and the review screen say so, and the portal GPA can differ for that reason (reference sheet B now computes 40.5/21 = 1.93 against the portal's 2.33). A blank final grade is no longer saved as INC; confirming requires a scale grade, INC, or DRP/W. Confirmed grade reports are immutable: updating a term confirms a new draft as the next `version`, links it with `supersedes_id`, and stamps the old report `superseded_at`. Only current versions (confirmed, not superseded) count. Drafts can be edited or deleted; confirmed versions cannot be deleted. Each new prediction stores `assessment_snapshot.grades` with the report ids, versions, and a copy of every subject row it used, so later updates never change it. Older predictions have no grade snapshot. Instructor names are kept out of saved descriptions: Faculty/Instructor/Professor/Section/Schedule/Room columns are ignored, the fallback parser drops tokens after the last remarks (or grade) token, and the normalizer strips a trailing honorific-led name or a trailing `SURNAME, Given` name (a single all-caps word after a comma, such as PURPOSIVE COMMUNICATION, ORAL, is kept) and flags the row for review. Headerless UCC portal rows follow the OCR column order (No, Code, Description, Faculty, Units, Section, Midterm, Final, Final Grade, Remarks): units are the last standalone digit, tokens after it are the section, and the faculty name before it is removed (surname before the last comma plus particles such as DELA or STA., or TBA); a report-level note says so. Existing stored rows are not rewritten; the View modal and new prediction snapshots show descriptions with instructor names removed, and updating the term saves cleaned descriptions. The grade UI offers Upload Document, Paste from UCC Portal, and Manual Entry and does not describe extraction as AI; the optional AI text fallback is disclosed only when it actually ran.
- M17.1: The UCC portal columns Faculty Name, Instructor, Professor, Year, Section, Schedule, and Room may be detected while a paste is split, then dropped. `subject_grades` has no instructor column. Confirmed reports are not rewritten. New imports and term updates save subject descriptions without professor names. The grade review table, grade history view, data export, and new prediction snapshots omit those names.
